# Changelog

Each release is listed here, newest first. [The development log](https://github.com/Deaversbp/expressive-charts/blob/main/docs/plan.md) records what each milestone built, and why.

## The 0.x promise

The library follows [semantic versioning](https://semver.org) from 0.1.0, with this promise for the 0.x releases.

**The effect-author API** is:

- `defineEffect` and `defineDataEffect`, with `GeometryEffectSpec` and `DataEffectSpec`;
- `matrix` and `offset`;
- `describe.bar`, `describe.arc`, `describe.line`, `describe.point` and `describe.shape`, with their specs: `BarSpec`, `BarSegmentSpec`, `Baseline`, `ArcSpec`, `LineSpec`, `PointSpec` and `ShapeSpec`;
- the effect contracts (`GeometryEffect`, `DataEffect`, `TransitionEffect`, `MarkEffect`, `AnyMarkEffect`, `Combined`), the contexts (`EffectContext`, `TransitionContext`) and where their text sits (`TextSpace`), the mark and its data (`MarkGeometry`, `Outline`, `Point`, `Rect`, `MarkData`, `Sample`), the drawing API (`Layer`, `MarkHandle`, `MarkStyle`, `Matrix`, `Paint`, `TextStyle`, `Color`, and the handles `IconHandle`, `PathHandle` and `TextHandle`), and icons as an effect gets them (`Icon`, `IconShape`, `IconSource`);
- the motion types the context uses: `MotionView`, `MotionMode`, `Timing`, `Tween`, `TweenOptions`, `TweenResult` and `Easing`;
- `expressive-charts/testing`: `checkEffect`, `checkTransition`, `fixtures`, `fixturePairs`, `testContext` and `play`, with their options (`CheckEffectOptions`, `CheckTransitionOptions`, `TestContextOptions`, `PlayOptions`), the fixtures' names (`FixtureName`, `FixturePairName`), the test context (`TestContext`) and what it records (`RecordingLayer`, `RecordingMark`, `Drawn`, `DrawnIcon`, `DrawnPath`, `DrawnText`, `LayerCall`, `MarkCall`, `Picture`), and the motion types they use: `Motion`, `Clock`, `ManualClock`, `ScalingOverrides` and `ScalingRule`.

That's every type these names use, so code written against them needs nothing outside the list. A test imports every name in it, so none can be renamed or removed by accident.

From 0.1.0:

- **A breaking change to that API comes only in a minor release** (0.1 → 0.2), never in a patch, and this file lists it with a migration note: what changed, and what to write instead.
- **A deprecated name keeps working for one minor release.** It's marked `@deprecated` with its replacement, and removed in the minor release after that.
- Additions (a new optional field, a new helper) can come in any release.

Everything else can still change in a minor release while the library is 0.x: the motion core (`motion`, `createMotion`, the clocks, `tween`, `animated`, `playback`, and the types the list doesn't name), the charts, the adapters, the built-in effects and the controls. Those changes are listed here too. [docs/effects-guide.md](https://github.com/Deaversbp/expressive-charts/blob/main/docs/effects-guide.md) is the guide to the author API.

## Unreleased

### Added

- **A line chart as a chart switch's view.** Its points grow into columns keyed as they are, and back: key the columns with the bar chart's `key` (``key: (d) => `goals@${d.week}` ``).
  - Each point pairs with its column and grows out of a dot of no size at its centre, or out of its own dot when it's alone between gaps, while the lines fade out over the first half. Back, each column shrinks into its point.
  - Between two line charts, the lines morph by series and their end labels move. The points stay hidden, but for a value alone between gaps, which morphs as its dot.
  - Focus follows the x: from an x to its first series' point's column, and back to the x, or to the point with `hover: "point"`.
- **`paintOf(key)` and `standsFor(key)` on `ChartSwitchView`,** both optional, with the `ChartSwitchPaint` type. `paintOf` gives the name a mark's colour comes from in the switch's assignment, and whether its chart draws it at rest; `standsFor` gives the keys a focus stop stands for, in the order the next view tries them. The bar, donut and line charts' handles have `paintOf`, and the line chart's has `standsFor`. A view without them is drawn by key, as before, so no page needs to change.
- **`texts` on `EffectContext`**, under the 0.x promise, with its type, `TextSpace`: where effects' text sits on the same chart or attachment, so an effect's text can keep clear of other effects' text. `box(content, style)` gives the box the text takes, measured as the chart measures its own labels (estimated where there's no layout); `held()` the boxes held by the runs that started before this one; and `hold(box)` says where this run's text is, until it holds another or the run is cleared. Every run on one runner shares one space. Our charts, `expressive()` and `fromVegaView()` always give it, and so does `testContext()`, with `held` in its options and `texts.holding` to read what a run holds. It's an optional field, an addition: an effect that ignores it works as before, and a context without it is still one.
- **`room` on `lineChart`:** px the layout keeps clear to the right of the end labels, for text an effect draws past them, such as a `delta`. The plot is that much narrower. Its default, 0, lays out as before; anything but a number of px, 0 or more, throws a `RangeError`, and `update({ room })` lays the chart out again.

### Changed

- **A slice's `nearbyLabels` are every other slice's labels,** in the slices' order, not only the nearest each way round: text that goes past a neighbour's label could meet the next one round. A page's effect that reads them sees more boxes; `delta` and `label` read them as before.
- **The runner tells an effect `onChange` when text held before its run's moved,** though its own mark didn't, once the chart has told every mark that moved, so the effect can place its text again. An effect that follows `onChange` already handles it.

### Fixed

- **`delta` and `label` keep clear of other effects' text.** Each goes past the text the runs before it hold (the first mark in the chart's order keeps its place, and the next goes past it), so two lines that end close together no longer put their changes on each other, and a line's `delta` no longer lands on its own `label`. On the season page's goals and xG lines, their changes met in 5 of the 9 matchweeks where both change at 1,000 px, and in 8 at 320; now in none.
- **Their text's own box keeps clear of labels beside it.** They checked a 6 px band along the way the text is placed, which text centred along a slice's ring reached past. Now, after passing the mark's own labels as before, the text moves along its way until its own box is clear: 6 px clear of a box the way misses, and past one the way meets as before. On 1,500 random donuts, 61 of the 963 slices whose label was dropped put their text on another slice's label, and now none does; such text also sits nearer its slice. A box the text would only meet further along its way isn't passed, as it was. Text that was clear stays where it was.

- **A chart switch draws each mark in its view's colour.** It drew each pair, and each mark that fades, in its key's colour, so columns coloured by series (the default) each took a colour of their own while they morphed, and the switch asked the shared assignment for a slot for every key. A switch whose views colour by key, such as a donut and its `colorBy: "category"` columns, draws as before.
- **`morph` keeps a line's gaps and a shape's holes.** Between two lines with gaps, it joined them part way; now the stroke inside a gap of the old line fades in as it goes, and inside a gap of the new line fades out, so nothing is drawn inside a gap both have and nothing jumps. Between two shapes with holes, such as two D3 rings, the holes showed only at the ends; now each hole morphs to its partner, largest with largest, and one with no partner closes up inside the shape as it moves, or opens from a point. A hole stays a hole under either fill rule. Lines without gaps and outlines without holes morph as before, byte for byte, so nothing to write instead.

## 0.5.0 (29 October 2026)

Curved lines and a hover on one point on the line chart, change labels that keep off other marks' labels, a negative column's value label off its name, curved Vega lines, and smaller pages for the motion core and `describe`. In the effect-author API, the one change is `nearbyLabels` on `MarkGeometry` and on the builders' specs, an addition. The other changes are outside the promise, and each says what to write instead, if anything.

### Added

- **`nearbyLabels` on `MarkGeometry`**, under the 0.x promise, and on each builder's spec (`BarSpec`, `ArcSpec`, `LineSpec`, `PointSpec` and `ShapeSpec`): the boxes of other marks' text near a mark, which an effect's text should keep clear of as well as its own. `labelBounds` stays the boxes of the mark's own. Our line chart gives each line every other line's end label, and the donut each slice its neighbours' labels, the nearest each way round; bars and adapters give none. It's an optional field, an addition: code that builds a `MarkGeometry` needs no change, and an effect that ignores it works as before. The builders check it as they check `labelBounds`, with a `RangeError` naming the field, such as `nearbyLabels[0].x`.
- **`curve` on `lineChart`.** `"linear"`, the default, draws straight lines as before, the same marks byte for byte. `"monotone"` is d3's `curveMonotoneX`: a smooth curve through every value, flat between two equal ones, that never goes above or below the values either side, so a line shows no value the data doesn't have. Each run between gaps is curved on its own, and a run of two values is straight.
  - A curved line is a polyline within 0.1 px of the curve, so its walk, gaps and reveal work as a straight line's, and no effect needs to change. Its samples are its rows' and one at each bend between them, each with its `at` and `value` on the curve, so `threshold` changes colour exactly where the drawn lines cross. A data effect that counts samples sees more than the rows on a curved line; `delta` and `label` read the ends, which are rows or the reveal.
  - A reveal between two rows ends the line on the curve, so playback draws it in. A change eases the curve with the rows, and `update({ curve })` eases each line from straight to curved, or back, without going past its values; Off jumps.
  - Anything but `"linear"` or `"monotone"` throws a `TypeError` naming it, and `update()` rejects it, changing nothing.

  It's a new option, and a line without it has the samples it had, so no page needs to change.

- **Curved Vega lines.** `fromVegaView()` reads a line Vega draws with any `interpolate` but `"linear"`, such as `"monotone"`, `"basis"`, `"step"` or `"natural"`: the path Vega drew, read with `describe.shape` from its `d`, moved into the marks' coordinates as the items are, at the item's stroke width. Its gaps come with it, one at each move, and a curve Vega closes on itself (the `-closed` ones) is a closed shape. Its samples are at the items drawn, on the curve, so `threshold`'s crossings between them are approximate, as on a D3 curve. It used to throw. A straight line is read from its items as before, the same mark, so no page needs to change.
- **A hover on one point on the line chart,** `lineChart({ hover: "point" })`. The pointer anywhere over the plot, and touch, hover the revealed point nearest it, alone (of two as near, the series first in `series`), and leaving the plot leaves. Its line and their decorations stay at full strength, and every other line and point dims, with its decorations, unless `dim` is false; text keeps its contrast. There's no crosshair: the tooltip sits above the point, or below it without room, with the x and that series' value.
  - The tooltip can be hovered from its point (WCAG 1.4.13). While it shows, the pointer stays on the hovered point while it's on its dot, though another point is nearer, and the tooltip's bridge reaches a px into its box, so the pointer goes straight from the point onto the tooltip without another point taking the hover on the way.
  - The points are the focus stops, one tab stop, each named by its x and its value, or by `markLabel` given that series alone. Left and Right go along the line, passing over its missing values, Up and Down to the point above or below, by where they're drawn, Home and End to the line's ends, and Page Up and Page Down a page along it.
  - Links still go by x, and a link's hover shows at every point there with nothing dimmed. `focus(key)` takes a point's key, or an x's.
  - `update({ hover })` changes it at once: a held hover ends, and focus moves to the nearest stop of the new kind. Anything but `"x"` or `"point"` throws a `TypeError`, and `update()` rejects it.

  The default, `"x"`, hovers every series at an x with the crosshair, as before, so no page needs to change.
- **A line chart's tooltip function is given the point's series** with `hover: "point"`, as a second argument, `(d, { series })`, for the tooltip's text and each point's description. With `"x"` it's given the row alone, so a function that takes the row alone still fits.

### Changed

- **Smaller pages that import only the motion core or `describe`.** A page that imports `motion` and `animated` is 1.7 KB gzipped, not 2.4, and one that imports `describe` and `matrix` 6.6 KB, not 7.2. They kept the tables the charts build when the package loads, such as the stylesheet's text and the time axis's steps, which are now marked so a bundler drops them when they aren't used. The same marks make pages that import charts up to 0.1 KB smaller, and the script-tag bundle 0.2 KB. Nothing to write instead.

### Fixed

- **`delta` and `label` keep off other marks' labels.** When two lines ended close together, with their end labels pushed apart, one line's text could land on the other's end label; now it goes past both. They still pick their way from the mark's own labels, so another mark's label only takes the text further that way, never turns it. And text centred on a point, within 45° of vertical, goes 6 px past a label's top or bottom, not past the side its way leaves through, where it could sit on the label it was placed past.
- **A negative column's value label no longer sits on its name.** The layout kept room under the plot for negative columns' value labels but drew the names in it, so the deepest column's value label was on its name. Now the names go below that room, and the plot keeps its height. A chart with no negative column draws as before. A `delta` on a negative column, past its name, reaches past the chart's bottom at 320 px (14.1 px in Chrome), as a column's does past the top; `room: 28` keeps it inside.

## 0.4.0 (27 October 2026)

Attachments that swap their effects and end their hover as charts do, `expressive()` reading circles and other SVG shapes through the new `describe.shape`, a chart switch in a link, Vega lines with gaps, the icon sets' faded parts, and a build with tsdown. In the effect-author API, `describe.shape`, `ShapeSpec`, and `fillOpacity` and `strokeOpacity` on `IconShape` are additions, and `checkEffect`'s default data on a gap is a fix, under Fixed: an effect that joins across a gap can now fail, as it should. The other changes are outside the promise, and each says what to write instead, if anything.

### Added

- **`describe.shape`**, under the 0.x promise, with its spec, `ShapeSpec`: a mark's geometry from SVG path data, `describe.shape({ key, series, d, matrix, width, labelBounds })`. The library follows the path itself, so it works the same in Node, Vitest and every browser. `d` is read as SVG reads it, up to its first error, and `matrix` moves it into the marks' px, as an element's transform does. A shape is closed when every subpath ends with `Z`, or where it started, and otherwise open.
  - An open shape is a line. Its walk follows the path, and each later move starts a new run after a gap, so a D3 line drawn with `.defined()` comes with its gaps. Its outline is the stroke, `width` px wide (default 1).
  - A closed shape, such as a D3 area, has no direction, like a point: its walk has length 0, at its centre. Its outline is the whole path, holes too, sampled round its longest subpath from its upper left, so a circle samples as `describe.point`'s does.
  - Béziers, and arcs that aren't circular, become straight pieces within 0.1 px of the curve, so path data still has only `M`, `L`, `A` and `Z`.
  - Path data with nothing to draw, a `matrix` that isn't six finite numbers and a `width` that isn't more than 0 each throw a `RangeError` naming the field.

  These are new names, so no code needs to change. The effects guide says how to check an effect on a curve or an area with it.

- **`fillOpacity` and `strokeOpacity` on `IconShape`**, under the 0.x promise: the fill's and the stroke's own opacity, each from 0 to 1 (default 1), inside the shape's `opacity`, so one shape can have a faint fill inside a full outline. `defineIcon` checks them, with a `RangeError` naming the shape and the field, and the SVG layer sets them on the shape's path. They're optional fields: code that builds an `IconShape` needs no change.
- **`expressive()` reads circles and shapes by their tags.** A `<circle>` is a point at its centre, with its radius, and a `<path>`, `<line>`, `<polyline>`, `<polygon>` or `<ellipse>` is a shape, read with `describe.shape` from its own path data, each through its transforms. So a D3 scatter, a D3 curve or area, `d3.symbol()` paths and Plot's dots need only a key, and a curve drawn with `.defined()` keeps its gaps.
  - A circle under an uneven scale or a skew is an ellipse, a shape. An open shape is as wide as its stroke as drawn, scaled by its transforms; a width of 0 reads as 1 px.
  - A circle with a numeric `value` gets it as its one sample, `{ t: 0, value }`, as a Vega symbol does. `segment` names a circle's or a shape's series, so a data effect can read it through `related`.
  - Each is a mark of its own: a key it shares with another element throws a `TypeError` naming the key. Circles and shapes keep document order, as marks described with `geometry` do. A shape SVG wouldn't draw, such as a path with no path data, isn't a mark until it draws something.
  - `watch` follows `x1`, `y1`, `x2`, `y2`, `rx` and `ry` too.

  Other elements (`<text>`, `<g>`, `<use>`, `<image>`) still throw, naming their tag. Elements that threw are read now, and a page's `geometry` still wins, so no page needs to change.
- **`update({ on })` and `leave()` on attachments.** `expressive()`'s and `fromVegaView()`'s attachments swap their effects in place, as a chart's `update({ on })` does: a slot given the same effect or preset name keeps its runs, a changed slot's new effect starts where the old one's runs were, and focus and the tab stop stay, so a page with an effect picker needn't attach again. It returns a promise, which resolves at once, and rejects, changing nothing, on an unknown preset name, a series a data effect needs that the marks don't have, or any option but `on`. `leave()` ends the hover, pointer or keyboard, as a chart's does, with focus staying where it is. Both are additions.
- **Vega lines with gaps.** `fromVegaView()` reads a line that Vega breaks at a point it leaves out (`defined: false`), as Vega-Lite 6 does at a missing value by default: the line has gaps, its samples have `gapBefore` after each, and no effect draws inside one. It used to throw. A line with no point drawn has no mark, as Vega draws nothing. A curve still throws.
- **A `chartSwitch` in a `link()`.** `link()` takes a chart switch as a source, through its view on show: hovering that view hovers the other sources, and their hovers hover it. The hidden view is never hovered, and its hovers aren't linked. While a switch plays, neither view can be reached, so it neither starts a link's hover nor shows one. A hover in the view it leaves ends as it starts, and the link hears it end; when it lands, the link's hover, if there is one, shows in the new view. A source is in one link at a time, a switch's views' charts with it: a switch whose view's chart is in a link throws, and so does a view's chart whose switch is in one. `link()` no longer throws on a switch, and its types read a switch's rows from its views' charts.
- **`on()`, `marks()` and `leave()` on `ChartSwitch`**, each the view on show's, as its chart's are. `on()` hears only the view on show, typed by the views' rows; `marks()` gives its marks, while a switch plays the marks of the view it's heading for; and `leave()` ends its hover. So a switch is a `LinkSource`, and a page can call them as on a chart.

### Changed

- **The package is built with tsdown, on Rolldown,** instead of tsup. Each entry has the same names, as an ES module and as CommonJS, with the same types, checked on TypeScript 5.4, 6 and 7. The files keep their names, but for the shared chunks, which are named by their first module. On the same code, the script-tag bundle is 6.6 KB smaller gzipped, and `expressive-charts/icons/sport` loads 4 KB with its chunks, not 9. Nothing to write instead.
- **A chart switch ends the old view's hover before `current` changes**, so `leave` listeners on that view's chart read `current` as the view the switch is leaving, not the one it's heading for. A page that wants the new view there takes it from the `show(view)` that started the switch. A `show()` such a listener calls runs once the switch has begun.

### Fixed

- **`checkEffect`'s default data on a gap**, under the 0.x promise. On a mark with gaps, such as the `"gapped line"` fixture, it has a sample at each end of each gap, with its `t` as its value and `gapBefore` on the one after, so a data effect sees the gap as on a line chart's line. Before, it had two samples, 0 at the start and 1 at the end, on every mark, so a data effect never saw a gap. On a mark without gaps it's as before. An effect that leaves the gap alone passes as it did; one that joins across a gap can now fail, as it should. A test that needs other data passes `data`.
- **`expressive()` takes a mark's colour as the browser computes it.** A fill or stroke that the page's CSS sets to black (or `none`) over the element's own colour attribute, or its group's, was read as the attribute's colour, so the hover colour and emphasis started from it. The fallback to the attributes is for jsdom, which computes no presentation attributes; the adapter now finds which it is, once a root `<svg>`. Nothing to write instead.
- **What effects draw for a mark stays with it.** The paths and icons an effect draws in the overlay, such as `threshold`'s runs and a riding `travel` ball, now take the transform another effect gives the mark, so they rock with a `wiggle` instead of coming up to 3 px apart from it. They fade with the mark when hover dims it, on our charts and on attachments with `dim`. Before, they stayed where they were, at full strength. Text in the overlay, such as `delta`'s and `label`'s, stays put and keeps its contrast, as a mark's labels do. No effect needs to change: the drawing API's types are as they were, and so are `checkEffect`'s checks. An effect that turns its mark and draws in the overlay where the turned mark is would now turn its drawing twice: draw on the mark as it is, and let the drawing follow. In the SVG, a run's paths and icons are in a `<g class="ec-follow">` in its group, so CSS that picked them out as its children (`.ec-run > path`) needs `.ec-run path`.
- **`iconFromSvg` keeps `fill-opacity` and `stroke-opacity`**, so an icon whose SVG fades a part's fill or stroke with them draws as its SVG does. Before, the faded part drew at full strength. They're read from attributes and `style`, as numbers or percentages, and inherited through groups as SVG inherits them: a shape's own replaces its group's, rather than multiplying as `opacity` does. A fill or stroke faded to 0 is dropped, as `none` is, and so is a shape left with neither. An icon made from SVG without them comes out the same. A long `width` or `height` on an `<svg>` with no viewBox is now read at once, too: a run of 100,000 digits followed by a letter took 23 s.

## 0.3.0 (27 October 2026)

A tooltip that can be hovered, change labels that hold up, lines that skip missing values, long axes, and more of the icon sets' SVG. In the effect-author API, `gaps` on `MarkGeometry`, `gapBefore` on `Sample`, `breaks` on `LineSpec`, and `fillRule` and `opacity` on `IconShape` are additions. Its one change is the `"gapped line"` fixture, with its migration note under Changed. The other changes are outside the promise, and each says what to write instead, if anything.

### Added

- **`fillRule` and `opacity` on `IconShape`**, under the 0.x promise. `fillRule` is `"nonzero"` (the default) or `"evenodd"`, which leaves a hole where the path's parts overlap. `opacity`, from 0 to 1 (default 1), fades the whole shape, its fill and stroke together. `defineIcon` checks them, with a `RangeError` naming the shape and the field, and the SVG layer draws them. They're optional fields: code that builds an `IconShape` needs no change.
- **`gaps` on `MarkGeometry`**, under the 0.x promise: the stretches of a mark's walk with no data, as `[from, to]` values of `t`, in order and apart. A line that skips a value has one, from the value before to the value after. The walk runs straight across a gap, so `start`, `end`, `length`, `path(t)`, `angle(t)` and `outline.sample(n)` work as on any walk; `slice(t0, t1)` and an open outline's `d` leave the gaps out, with a move across each. It's an optional field: code that builds a `MarkGeometry` needs no change, and no mark has gaps unless a line skips a value. An effect that draws its own path from `path(t)` would draw across a gap, so draw along a walk with `slice()`, as the effects guide says.
- **`breaks` on `LineSpec`**, under the 0.x promise: `describe.line({ points, breaks })` takes the indices of the points that start a new run, so there's a gap from `points[i - 1]` to `points[i]`. Each is a whole number from 1 to the last index, in order, with no repeats; anything else throws a `RangeError` naming it (`breaks[1]`). So a page describes a D3 line drawn with `.defined()` by its defined points and where they break. An optional field: code without it needs no change.
- **`gapBefore` on `Sample`**, under the 0.x promise: `true` on the first sample after a gap, so a data effect doesn't join it to the one before. `samplesAlong()` sets it from the mark's gaps, and `expressive()` keeps it on the samples a page gives. An optional field.
- **Missing values on `lineChart`.** `series` take fields of `number | null | undefined`, and a value that's `null` or `undefined` is missing: a gap in its line, from the value before to the value after, with no point. It used to throw. The x stays a stop: the crosshair stops there, and its name, the tooltip and the data table say the series is missing ("3: goals missing, 3.6 xg"). At an x with every value missing there's no point to ring, so keyboard focus there is a 2 px line in `--ec-focus` where the crosshair is, which stays when Escape hides the crosshair. A value alone between gaps shows its point at rest; a line revealed into a gap ends at its last value, with its end label there; and a line with no values is empty. Its samples leave the missing values out, with `gapBefore` after each gap, so `threshold` colours nothing there and `travel` jumps across. A gap opens or closes as a change starts, a value that comes growing out of the line. `NaN` and the infinities still throw. `markLabel`'s summary lists only the values an x has.
- **Effects across a gap.** `travel` jumps: its icon is never drawn over a gap, and goes from one side to the other at once, inset from each run's ends as from the walk's. Its trip's time counts only the runs it's drawn on, and a run shorter than the icon is passed at once, unless it's the last, where the icon rests at the last value. `threshold` doesn't interpolate across a `gapBefore`, in the mark's samples or the reference's, so where either has no value nothing is coloured. `trace`, `pulse`, `flash`, `wiggle`, `delta` and `label` skip gaps unchanged. No built-in effect draws inside a gap.
- **`room` on `barChart`**: px the layout keeps clear past the labels at each end of the value axis that bars reach, for text an effect draws there, such as a `delta`. Default 0, so nothing moves. At 320 px, `room: 28` keeps a bar's, a column's and a negative bar's `delta` inside the chart, so a page no longer pads the chart's container for it. Anything but a number of px, 0 or more, throws a `RangeError`.
- **Page Up and Page Down** on every chart, and on an attachment with `keyboard: true`. They move focus a page on or back and stop at the ends, as the arrows do: a tenth of the marks, rounded up, or on a line chart's time axis a calendar month in its `timeZone`, to the first x a month or more away. A month on keeps the day, or ends a shorter month on its last day: 31 January goes to 28 February. So ten years of days is 120 presses, not 3,653. With Alt, Ctrl or Meta they're still the browser's.

### Changed

- **`"gapped line"` in `FixtureName` and `fixtures`**, under the 0.x promise: the line fixture with a gap after its second point, a run either side. So `checkEffect` runs every effect on it too, by default: an effect that fails its checks on a mark with gaps fails where it passed before. Code that maps every fixture's name, such as a `Record<FixtureName, …>`, needs one more entry: `"gapped line": …`. Code that only reads fixtures, or passes its own `marks`, needs no change.
- **An update ends the last one's `update` effects on the marks it leaves alone**, as a re-trigger would: a `delta` goes at its chart's next update, and a `flash` still playing stops there. An update is a chart's `update()` with `data`, even if no value changed (a matchweek where nobody scores), or one that changes a value or adds or removes a mark; or an attachment's `refresh()` that finds a new row, a new value, or a mark entering or leaving. `update({ on })` alone, a re-sort, a resize, a line's `reveal()`, and a `refresh()` that finds nothing new (a Vega render for a hover signal) keep them. Before, an update effect stayed until its own mark's next update, so a page emptied the slot itself (`update({ on: {} })`) before each update; that's no longer needed, and can go. To keep something past the next update, put it in `decorate`.
- **Overlay text on attachments is sized as on our charts**: 12.5 px, weight 600, with tabular digits, in the theme's text colour, by a new `.ec-overlay .ec-text` rule. So `delta`'s and `label`'s text on an `expressive()` or `fromVegaView()` attachment no longer takes the host page's text size. The rule is in `:where()`, so a page's own CSS still wins: for the page's size, as before, add `.ec-overlay .ec-text { font-size: inherit; font-weight: inherit; }`, or size it in the page's own rule, such as `#slope .ec-text { font-size: 11px; }`.
- **A bar chart thins labels that would overlap.** Past about 40 bars, its labels overlapped. Now it draws every nth category label, from the first, with n the smallest of 1, 2, 5, 10, 20, 50 and so on that leaves none overlapping, and its value labels all or none: none when any two would overlap. The marks' names, the tooltip, the legend and the data table keep every name and value; `labelBounds` and `labels()` have only the labels drawn. A chart whose labels didn't overlap looks as it did, and there's no option. A page that thinned the labels itself, with CSS such as `.ec-mark:not([data-key$="0"]) .ec-label { display: none; }`, should drop that rule, which now thins them twice. To show every name, give the chart room for them: more `height` for bars, more `width` for columns, or fewer bars.

### Fixed

- **An update run's `data.previous` holds the values the last update gave**, not the values part way through a change still playing. So an update that replaces one still moving says "+1" with `delta`'s default `value`, not "+1.88", and a page no longer needs a `value` that reads its rows to get it right. The values before are the data the mark last rested at: its last update, or where it's been since without a transition (a resize, a line's reveal). The `previous` geometry, and an `update` event's `from`, are still the mark on screen, which the transition starts from.
- **`iconFromSvg` keeps `fill-rule` and `opacity`**, so an icon whose SVG has an even-odd hole (Heroicons' solid style) or a faded part (a duotone set's) draws as its SVG does. Before, the hole filled in and the faded part drew at full strength. They're read from attributes and `style` and inherited through groups, with a group's opacity multiplied into its shapes'. A shape with an opacity of 0 is dropped. `fill-opacity` and `stroke-opacity` still aren't kept.
- **`import "expressive-charts/style.css"` typechecks on TypeScript 6 and 7.** From TypeScript 6, a side-effect import must find something (`noUncheckedSideEffectImports` is on by default), and the stylesheet had no types, so the import was error TS2882. Its export now has types, an empty module (`dist/expressive-charts.css.d.ts` and `.d.cts`), and bundlers and Node still load the CSS. It keeps a plain `default` too, so a CSS `@import` (css-loader's) and Sass, which resolve with conditions such as `style`, still find it. Nothing changes on TypeScript 5.4 to 5.9.
- **The tooltip can be hovered** (WCAG 1.4.13, the accessibility audit's one fail). It took no pointer, so moving onto it hovered whatever was under it, or nothing, which hid it. Now, while it shows, the pointer on it stays on the mark or x it's for, so its text can be read, selected and magnified: leaving it for a mark hovers that mark, and leaving it for anything else ends the hover. Beside a mark, a clear bridge over the 12 px gap leads to it, and one that comes up under a resting pointer, as a crosshair's can, lets the pointer through until the pointer is off it. It looks the same, and Escape still hides it. While it shows it covers the marks under it: reach them round it, or by keyboard.

## 0.2.0 (26 October 2026)

Built-in effects that explain a change, text that keeps clear of a mark's own labels, and hover linked across charts. Nothing in the effect-author API breaks: its one change, `labelBounds`, is an addition. The other changes are outside the promise, and each says what to write instead, if anything.

### Added

- **`trace`**, a built-in effect: a highlighter stroke drawn along a mark's walk, which stays. `trace({ color, width, opacity, duration })` draws in the overlay and leaves the mark itself untouched, so it's safe in any slot. On a stack it runs the whole walk, and on a point it draws nothing. Its end state is the whole stroke. It isn't a preset. The effects guide's `trace` stays as its worked example, a smaller version.
- **`link(sources, { by, effects })`**: linked hover across charts and attachments. When one source is hovered by the pointer, touch or the keyboard, the others hover their marks with the same linking value: by default a line point's x, else a mark's key, so a column keyed by its matchweek links with the line's x there. `by(event)` gives the value instead, typed by the sources' rows. Linked marks get their chart's emphasis, dimming and hover effect, with `source: "linked"` on their `hover` event, and no tooltip, focus or announcement; `effects: false` keeps them to emphasis and dimming. The newest hover in a link is the one shown, and Escape or `leave()` on the hovered source ends them all. A source can be in one link at a time, and a `chartSwitch` can't be linked yet. With its types, `Link`, `LinkOptions` and `LinkSource`.
- **`labelBounds` on `MarkGeometry`**, under the 0.x promise: the boxes of the text the chart draws for a mark, so an effect's own text can keep clear of them. Our charts fill it in: a bar's category and value labels, the two lines of a slice's label outside the ring, a line's end label, each where it's drawn in every frame of a change, a reveal and a resize. Segments, points and marks the library didn't draw have none. `describe.bar`, `.arc`, `.line` and `.point` take it in their specs and pass it through, so a page that describes host marks can give it, and `expressive()` keeps it. It's an optional field: code that builds a `MarkGeometry` needs no change, and an effect that ignores it works as before.
- **`delta` and `label`**, built-in data effects that put text past the end of a mark, clear of its own labels: past a bar's value label, above a column's, past a line's end label, outside a slice's label, and 10 px past the end of a mark with none. `delta({ value, format, color })`, for the `update` slot, says the change since the last update ("+2"), worded in the page's locale with its sign and at most two decimals; with no previous values, or no change, it draws nothing. `label(text, { color })`, usually for `decorate`, says what `text(data, mark)` works out from the mark's data, and is typed by the rows it reads. Both rise 8 px into place and stay, following the mark, so their end state shows the text. The text is in the overlay, which screen readers don't read: say the same in the table or the announcement. With their types, `DeltaOptions` and `LabelOptions`. The effects guide's `delta` stays as its worked example, a smaller version.

### Changed

- **`travel`'s trip lasts at most 4 s base**, after the gait's pace. A trip along more than 1,440 px (about 1,250 px for a step) is shorter than before: the icon goes faster rather than longer, so with `stagger` in front it still ends within 5 s. Analysis and Off scale it as before. Nothing needs to change in your code; for a long walk at the old speed, carry the icon in an effect of your own (`defineEffect`).
- **A `hover` event's `source` can be `"linked"`**, for a mark `link()` hovered because a mark in another chart was. Code that switches on `source` exhaustively gets a type error: add a `"linked"` case, or handle it with `"pointer"` where a linked mark should act as a hovered one. Without `link()`, `source` is never `"linked"`.
- **A mark's effects hear `onChange` when its own labels move**, even when the mark doesn't: a line's end label pushed aside by another's, or a label whose text changed. So do a bar's and a slice's when only their row changed, as a line's already did, so a decoration that reads a field the chart doesn't plot follows it. An effect that redraws on every change does a little more work; nothing needs to change in your code.
- **Hover dims the other marks' bodies, not their labels**, on the bar and donut charts and in a chart switch. The names and values of the marks that aren't hovered stay at full strength, so they keep 4.5:1 (WCAG 1.4.3); they used to dim with their marks, to 2.0:1 in the light theme. `--ec-dim-opacity` keeps its default, 0.3, and an effect's `opacity` on a dimmed mark still multiplies with it. `expressive()`'s `dim` doesn't change. To dim the labels too, as before, add this to the page's CSS: `.ec-chart.ec-hovering .ec-mark:not(.ec-hot) :is(.ec-label, .ec-value) { opacity: var(--ec-dim-opacity, 0.3); }`.

## 0.1.0 (24 October 2026)

The first release, published to npm from CI with provenance. Everything in it is new. [docs/api.md](https://github.com/Deaversbp/expressive-charts/blob/main/docs/api.md) documents every export.

### What's in it

- **The motion core.** One clock and three modes: Presentation (data transitions staged over about a second), Analysis (at most about 200 ms, unstaged) and Off. The device's reduced-motion setting turns motion off unless the viewer picks a mode on the page; a mode the page sets in code never overrides it. With motion off, every animation jumps to its end state. `motion` and `createMotion`, the clocks (`defaultClock`, `createClock`, `manualClock`), `tween`, `animated` with its interpolators, the easings, and `playback`, which plays a value through a range.
- **Bar, donut and line charts.** `barChart` draws bars or columns, plain or stacked; `donutChart` shares of a total; `lineChart` a line per series, on a number axis or a time axis. Each sizes itself to its container, follows the light or dark theme, gives every mark a key, and has a tooltip, a legend, a data table and keyboard focus, with announcements as an option. Colours follow the entity, not its rank (`colorAssignment`). The handle has `update()`, which animates a change by the motion mode (in Presentation, values first and then positions), `on()` for mark events, `marks()`, `focus(key)`, `leave()`, `labels()` and `destroy()`.
- **Switching between charts.** `chartSwitch` shows views of the same data in one place, and turns each mark into its partner in the next with `morph()`.
- **Adapters.** `expressive()` brings the same effects, keyboard focus and names to SVG marks drawn by D3, Observable Plot or by hand. It draws on an overlay and leaves the host's styling alone. `fromVegaView()` does the same for Vega and Vega-Lite charts rendered as SVG, and `samplesAlong()` gives data effects their samples on such marks.
- **Effects.** `travel` carries an icon along a mark, rolling, stepping or sliding (`gaits`); `flash`, `wiggle` and `pulse` draw attention without changing a value; `threshold` colours a mark where it's below or above a reference; `morph` turns one mark into another. `sequence`, `parallel`, `stagger` and `only` put effects together. Each goes in an effect slot (`hover`, `enter`, `update`, `exit`, `decorate`), as an effect or a preset's name, and `registerPreset` adds names.
- **Icons.** A neutral core set in theme colours (`icons`: a dot, an arrow and a chevron), `defineIcon` and `iconFromSvg` for your own, `registerIcon` and `registerIcons` to use them by name, and a ball and a boot in `expressive-charts/icons/sport`.
- **Controls.** `motionSwitch()`, the viewer's own choice of mode, kept across pages if you ask; `playButton()`, the Play/Pause button for a playback (WCAG 2.2.2).
- **Styling.** One injected stylesheet, or `expressive-charts/style.css` as a file; `--ec-*` custom properties for theming; and `configure()` for a Content-Security-Policy nonce, or for injecting nothing.
- **The effect-author API**, under the 0.x promise above: `defineEffect`, `defineDataEffect`, `describe`, `matrix`, `offset` and the contracts, with `expressive-charts/testing` (`checkEffect`, `checkTransition`) to check an effect on every kind of mark.
- **Accessibility.** Each chart is a named group and each mark one named image. A data table follows every chart, keyboard focus plays the hover effects, Escape ends a hover, and nothing plays by itself. The demo pages are checked against WCAG 2.2 AA, with axe's rules in Chromium, Firefox and WebKit, and with screen-reader scripts for NVDA + Chrome.
- **Packaging.** ES modules and CommonJS, each with its own types, which need TypeScript 5.4 or newer. No runtime dependencies and no side effects in its JavaScript, so a bundler keeps only what a page imports. A script-tag bundle defines one global, `ExpressiveCharts`. Node.js 22 or newer imports it with no DOM.

### In more detail

What each part does, and behaviour worth knowing:

- **The effect-author API** ([guide](https://github.com/Deaversbp/expressive-charts/blob/main/docs/effects-guide.md)). `defineEffect(spec)` and `defineDataEffect<D>(spec)` make an effect from its `run` and `end`: they fill in the kind and a `clear()` that does nothing, throw a `TypeError` without `run` or `end` (every effect needs an end state), and freeze the effect. A data effect's spec is checked against its row type strictly.
- **`expressive-charts/testing`**, a separate entry with the conformance suite. `checkEffect(effect, { marks, icons, data, batch, moved, name })` runs five checks on every mark (a full run ends as `end()` draws; clearing leaves nothing; an abort settles; with motion off no frames run; after a run or `end()`, a `change()` to the mark moved somewhere else leaves what `end()` draws there) and throws one `Error` listing every failure, in any test runner. The fixtures have moved twins for the fifth check; a page's own marks pass `moved(mark)` or skip it. With it: `fixtures` (one of each kind of mark), `testContext` and `play`.
- **`threshold({ compareTo, when, color })`** is the built-in data effect. It colours the parts of a mark's walk where its values are below a constant or a related series (`when: "above"` for above), in `"negative"` by default, with crossings interpolated between samples. A series is matched by `at` where both have it, else by `t`, and goes in `needs.related`. It draws at once, with no animation, and redraws on every change, so it belongs in `on.decorate`.
- **`samplesAlong(mark, points)`** gives data effects their samples on marks the library didn't draw. It projects each point `{ x, y, value, at? }`, in the marks' coordinates, onto the nearest point of the mark's walk and returns the samples in `t` order; a point on the walk, such as a vertex of the line it drew, lands exactly there. It pairs with `expressive()`'s `samples` option, and its points' type is `SamplePoint`.
- **`expressive()`'s `watch` option** follows the host's own transitions frame by frame, without `refresh()`. A `MutationObserver` notes the marks' geometry attributes, and `transform` and `style` on their ancestors up to the `<svg>`; once a frame, only the marks that moved are read again (their rows, geometry and samples), and their effects follow with no events. `refresh()`, called when the host joins new data, still fires `enter`, `update` and `exit`. It's opt-in: its cost grows with the number of marks that move each frame.
- **Transition effects.** `TransitionEffect`'s `run(from, to, ctx)` and `end(from, to, ctx)` take a `TransitionContext`: an `EffectContext` with `start`, from 0 to 1, so a run can begin part way and a switch back mid-way retraces. Its `mark` does nothing and its `onChange` never fires, since both views' marks are hidden while a transition plays.
- **`checkTransition(effect, { pairs, icons, name })`** in `expressive-charts/testing` checks a transition effect on pairs of marks, both ways: checks 1 to 4 of `checkEffect`, a run from `start: 0.5`, and that a run back from `start: 1 − p` begins with the picture the run forward draws at p. Its default pairs are `fixturePairs`: a slice and a column, a bar and a column, two slices, two lines and two points.
- **`morph({ points, align })`** is the built-in transition effect. It samples two closed outlines at `points` (default 160) and moves each point in a straight line to its partner, as one filled path; two lines are sampled along their strokes, their width moving between thicknesses; a closed and an open outline crossfade. `align: "unroll"` matches each side with the same side, and `"drop"` turns the matching by a side from the mark that goes round its pivot, so a slice's outer arc meets a column's top. The default is `"unroll"`, picked by comparing the two in the morph demo. 950 ms base with `transition` timing, eased in and out; a run from `start` takes the rest of the time.
- **`chartSwitch(target, { views, initial, transition, colors, announce })`** shows views of the same data in one place, one at a time, and turns each mark into the mark with its key in the next with a transition effect, `morph()` by default. Each view is a function that draws its chart in the container it's given, with the switch's `ColorAssignment`. Labels move between their places and swap their text half way, unmatched marks fade, and the old view's other parts fade out as the new one's fade in. A `show()` back mid-way reverses from where the shapes are. Only the shown view can be seen, reached or read, focus on a mark follows its key, and `announce` says the new view's label. It returns `{ show(view), current, chart(view), destroy() }`.
- **Dates on `lineChart`'s x.** An `x` that gives `Date`s makes a time axis, with no dependency. Its ticks fall on second, minute, hour, day, week, month and year boundaries, at both ends and a step of about a quarter of the range, each worded for its level in the page's locale through `Intl.DateTimeFormat` ("2026", "Apr", "Feb 8", "3:00 PM"). Each x is said as a medium date ("Jan 5, 2026", with the time when any x has one) in its name, the tooltip's title, the table's row headers and announcements, and `xFormat(x)` words it instead. `timeZone` is `"UTC"` (the default) or `"local"`. A date's key is its ISO string (`goals@2026-01-05T00:00:00.000Z`), samples' `at` is a `Date`, and `reveal()` takes a `Date` or its time in ms. Numbers and dates together throw a `TypeError`, as does an invalid `Date`. `LineChartOptions.x` is `Accessor<D, number | Date>`.
- **`update({ on })`** swaps a chart's effects in place, on the bar, donut and line charts: a changed slot's runs are cleared and the new effect starts where they were. `decorate` starts again on every mark, a held hover replays with the new hover effect once the change settles, and `enter`, `update` and `exit` draw the new effect's end state, so nothing enters again. Focus stays, and a slot given the same effect or preset name keeps its runs. An unknown preset name rejects before anything changes.
- **`leave()`** on every chart handle ends its hover, pointer or keyboard, as the viewer moving away would, and fires `leave`. Focus stays where it is. A chart switch ends the old view's hover with it, so `ChartSwitchView` has `leave()` too.
- **`table.series`** heads each series' column in the data table, `{ shots: "Shots" }`, defaulting to its `seriesLabels` name. It names a donut's value column without renaming its slices or its centre.
- **`fromVegaView(view, options)`** attaches effects to a Vega or Vega-Lite chart rendered as SVG. It reads the named mark (`mark`, Vega-Lite's `"marks"` by default) from the View's scenegraph: rects are bars (stacks too), arcs slices, symbols points and lines lines. `sample(row)` gives data effects each item's value and `at`. It takes `expressive()`'s other options, and follows the View's own renders, new data or a resize, with no `refresh()` to call. Duck-typed on the View: the library imports nothing from Vega, which stays a dev dependency.
- **Icons from icon sets.** `iconFromSvg` keeps `polyline` beside `path`, `circle`, `rect`, `ellipse`, `line` and `polygon`, drawn as a polygon left open, and `currentColor`, in any case, becomes the `text` token. So an icon copied from a set such as Lucide, Heroicons or Tabler follows the chart's theme, not the page's `color`. Fill rules and opacity aren't kept, so a solid icon's holes can fill in. The Icons section of docs/api.md has a recipe.
- `sequence` starts each part on the mark's geometry and data as they are when that part starts, not as they were when the sequence started, so a part after a travel follows a line that grew meanwhile.
- `onChange` listeners in the `update` slot get data that keeps the previous values the run was given, so `stagger` and `sequence` keep them when they start an effect on the latest data.
- `expressive()`'s hovered mark under `dim: true` takes its strong colour as our charts' marks do: its colour stepped a quarter of the way toward `--ec-text` (in OKLab), so lighter in the dark theme. `emphasis` on host marks mixes toward the same colour.
- `expressive()` reads a `<rect>` through its parent's coordinates and its own `transform` attribute, not through its own screen CTM, so the CSS transform an effect gives a bar is never read back as geometry. A CSS transform a host puts on the rect element itself isn't seen either (on its groups, it is).
- **CommonJS has its own types.** Each entry's `require` condition points at `.d.cts` declarations, so a CommonJS project resolving with `node16` is given CommonJS types for the `.cjs` file it loads. `import` has the `.d.ts` files.
- The types need TypeScript 5.4 or newer, since they use `NoInfer`. Under the old `node10` resolution, TypeScript can't find the subpath entries' types.
- The package includes this changelog, where the promise is.
- **Escape dismisses a pointer's hover.** While something is hovered, Escape anywhere on the page ends the hover and hides the tooltip, as `leave()` does, so the tooltip can be dismissed without moving the pointer (WCAG 1.4.13). An Escape the page has already handled is left alone.
- With `markLabel`, `expressive()` takes an `img`, `graphics-symbol` or `graphics-object` role (and its `aria-roledescription`) off unnamed host elements around the marks it names, as Vega gives the groups round its lines, so each mark is read once, by its name. `destroy()` puts them back.
- Under forced colours (Windows contrast themes), the motion switch's pressed mode shows in `Highlight` and `HighlightText`.
