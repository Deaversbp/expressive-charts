# Changelog

Each release is listed here, newest first. [The development log](https://github.com/Deaversbp/expressive-charts/blob/main/docs/plan.md) records what each milestone built, and why.

## The 0.x promise

The library follows [semantic versioning](https://semver.org) from 0.1.0, with this promise for the 0.x releases.

**The effect-author API** is:

- `defineEffect` and `defineDataEffect`, with `GeometryEffectSpec` and `DataEffectSpec`;
- `matrix` and `offset`;
- `describe.bar`, `describe.arc`, `describe.line` and `describe.point`, with their specs: `BarSpec`, `BarSegmentSpec`, `Baseline`, `ArcSpec`, `LineSpec` and `PointSpec`;
- the effect contracts (`GeometryEffect`, `DataEffect`, `TransitionEffect`, `MarkEffect`, `AnyMarkEffect`, `Combined`), the contexts (`EffectContext`, `TransitionContext`), the mark and its data (`MarkGeometry`, `Outline`, `Point`, `Rect`, `MarkData`, `Sample`), the drawing API (`Layer`, `MarkHandle`, `MarkStyle`, `Matrix`, `Paint`, `TextStyle`, `Color`, and the handles `IconHandle`, `PathHandle` and `TextHandle`), and icons as an effect gets them (`Icon`, `IconShape`, `IconSource`);
- the motion types the context uses: `MotionView`, `MotionMode`, `Timing`, `Tween`, `TweenOptions`, `TweenResult` and `Easing`;
- `expressive-charts/testing`: `checkEffect`, `checkTransition`, `fixtures`, `fixturePairs`, `testContext` and `play`, with their options (`CheckEffectOptions`, `CheckTransitionOptions`, `TestContextOptions`, `PlayOptions`), the fixtures' names (`FixtureName`, `FixturePairName`), the test context (`TestContext`) and what it records (`RecordingLayer`, `RecordingMark`, `Drawn`, `DrawnIcon`, `DrawnPath`, `DrawnText`, `LayerCall`, `MarkCall`, `Picture`), and the motion types they use: `Motion`, `Clock`, `ManualClock`, `ScalingOverrides` and `ScalingRule`.

That's every type these names use, so code written against them needs nothing outside the list. A test imports every name in it, so none can be renamed or removed by accident.

From 0.1.0:

- **A breaking change to that API comes only in a minor release** (0.1 → 0.2), never in a patch, and this file lists it with a migration note: what changed, and what to write instead.
- **A deprecated name keeps working for one minor release.** It's marked `@deprecated` with its replacement, and removed in the minor release after that.
- Additions (a new optional field, a new helper) can come in any release.

Everything else can still change in a minor release while the library is 0.x: the motion core (`motion`, `createMotion`, the clocks, `tween`, `animated`, `playback`, and the types the list doesn't name), the charts, the adapters, the built-in effects and the controls. Those changes are listed here too. [docs/effects-guide.md](https://github.com/Deaversbp/expressive-charts/blob/main/docs/effects-guide.md) is the guide to the author API.

## Unreleased

### Added

- **`fillRule` and `opacity` on `IconShape`**, under the 0.x promise. `fillRule` is `"nonzero"` (the default) or `"evenodd"`, which leaves a hole where the path's parts overlap. `opacity`, from 0 to 1 (default 1), fades the whole shape, its fill and stroke together. `defineIcon` checks them, with a `RangeError` naming the shape and the field, and the SVG layer draws them. They're optional fields: code that builds an `IconShape` needs no change.
- **`room` on `barChart`**: px the layout keeps clear past the labels at each end of the value axis that bars reach, for text an effect draws there, such as a `delta`. Default 0, so nothing moves. At 320 px, `room: 28` keeps a bar's, a column's and a negative bar's `delta` inside the chart, so a page no longer pads the chart's container for it. Anything but a number of px, 0 or more, throws a `RangeError`.

### Changed

- **An update ends the last one's `update` effects on the marks it leaves alone**, as a re-trigger would: a `delta` goes at its chart's next update, and a `flash` still playing stops there. An update is a chart's `update()` with `data`, even if no value changed (a matchweek where nobody scores), or one that changes a value or adds or removes a mark; or an attachment's `refresh()` that finds a new row, a new value, or a mark entering or leaving. `update({ on })` alone, a re-sort, a resize, a line's `reveal()`, and a `refresh()` that finds nothing new (a Vega render for a hover signal) keep them. Before, an update effect stayed until its own mark's next update, so a page emptied the slot itself (`update({ on: {} })`) before each update; that's no longer needed, and can go. To keep something past the next update, put it in `decorate`.
- **Overlay text on attachments is sized as on our charts**: 12.5 px, weight 600, with tabular digits, in the theme's text colour, by a new `.ec-overlay .ec-text` rule. So `delta`'s and `label`'s text on an `expressive()` or `fromVegaView()` attachment no longer takes the host page's text size. The rule is in `:where()`, so a page's own CSS still wins: for the page's size, as before, add `.ec-overlay .ec-text { font-size: inherit; font-weight: inherit; }`, or size it in the page's own rule, such as `#slope .ec-text { font-size: 11px; }`.

### Fixed

- **An update run's `data.previous` holds the values the last update gave**, not the values part way through a change still playing. So an update that replaces one still moving says "+1" with `delta`'s default `value`, not "+1.88", and a page no longer needs a `value` that reads its rows to get it right. The values before are the data the mark last rested at: its last update, or where it's been since without a transition (a resize, a line's reveal). The `previous` geometry, and an `update` event's `from`, are still the mark on screen, which the transition starts from.

- **`iconFromSvg` keeps `fill-rule` and `opacity`**, so an icon whose SVG has an even-odd hole (Heroicons' solid style) or a faded part (a duotone set's) draws as its SVG does. Before, the hole filled in and the faded part drew at full strength. They're read from attributes and `style` and inherited through groups, with a group's opacity multiplied into its shapes'. A shape with an opacity of 0 is dropped. `fill-opacity` and `stroke-opacity` still aren't kept.
- **`import "expressive-charts/style.css"` typechecks on TypeScript 6 and 7.** From TypeScript 6, a side-effect import must find something (`noUncheckedSideEffectImports` is on by default), and the stylesheet had no types, so the import was error TS2882. Its export now has types, an empty module (`dist/expressive-charts.css.d.ts` and `.d.cts`), and bundlers and Node still load the CSS. It keeps a plain `default` too, so a CSS `@import` (css-loader's) and Sass, which resolve with conditions such as `style`, still find it. Nothing changes on TypeScript 5.4 to 5.9.

## 0.2.0 (26 October 2026)

Built-in effects that explain a change, text that keeps clear of a mark's own labels, and hover linked across charts. Nothing in the effect-author API breaks: its one change, `labelBounds`, is an addition. The other changes are outside the promise, and each says what to write instead, if anything.

### Added

- **`trace`**, a built-in effect: a highlighter stroke drawn along a mark's walk, which stays. `trace({ color, width, opacity, duration })` draws in the overlay and leaves the mark itself untouched, so it's safe in any slot. On a stack it runs the whole walk, and on a point it draws nothing. Its end state is the whole stroke. It isn't a preset. The effects guide's `trace` stays as its worked example, a smaller version.
- **`link(sources, { by, effects })`**: linked hover across charts and attachments. When one source is hovered by the pointer, touch or the keyboard, the others hover their marks with the same linking value: by default a line point's x, else a mark's key, so a column keyed by its matchweek links with the line's x there. `by(event)` gives the value instead, typed by the sources' rows. Linked marks get their chart's emphasis, dimming and hover effect, with `source: "linked"` on their `hover` event, and no tooltip, focus or announcement; `effects: false` keeps them to emphasis and dimming. The newest hover in a link is the one shown, and Escape or `leave()` on the hovered source ends them all. A source can be in one link at a time, and a `chartSwitch` can't be linked yet. With its types, `Link`, `LinkOptions` and `LinkSource`.
- **`labelBounds` on `MarkGeometry`**, under the 0.x promise: the boxes of the text the chart draws for a mark, so an effect's own text can keep clear of them. Our charts fill it in: a bar's category and value labels, the two lines of a slice's label outside the ring, a line's end label, each where it's drawn in every frame of a change, a reveal and a resize. Segments, points and marks the library didn't draw have none. `describe.bar`, `.arc`, `.line` and `.point` take it in their specs and pass it through, so a page that describes host marks can give it, and `expressive()` keeps it. It's an optional field: code that builds a `MarkGeometry` needs no change, and an effect that ignores it works as before.
- **`delta` and `label`**, built-in data effects that put text past the end of a mark, clear of its own labels: past a bar's value label, above a column's, past a line's end label, outside a slice's label, and 10 px past the end of a mark with none. `delta({ value, format, color })`, for the `update` slot, says the change since the last update ("+2"), worded in the page's locale with its sign and at most two decimals; with no previous values, or no change, it draws nothing. `label(text, { color })`, usually for `decorate`, says what `text(data, mark)` works out from the mark's data, and is typed by the rows it reads. Both rise 8 px into place and stay, following the mark, so their end state shows the text. The text is in the overlay, which screen readers don't read: say the same in the table or the announcement. With their types, `DeltaOptions` and `LabelOptions`. The effects guide's `delta` stays as its worked example, a smaller version.

### Changed

- **`travel`'s trip lasts at most 4 s base**, after the gait's pace. A trip along more than 1,440 px (about 1,250 px for a step) is shorter than before: the icon goes faster rather than longer, so with `stagger` in front it still ends within 5 s. Analysis and Off scale it as before. Nothing needs to change in your code; for a long walk at the old speed, carry the icon in an effect of your own (`defineEffect`).
- **A `hover` event's `source` can be `"linked"`**, for a mark `link()` hovered because a mark in another chart was. Code that switches on `source` exhaustively gets a type error: add a `"linked"` case, or handle it with `"pointer"` where a linked mark should act as a hovered one. Without `link()`, `source` is never `"linked"`.
- **A mark's effects hear `onChange` when its own labels move**, even when the mark doesn't: a line's end label pushed aside by another's, or a label whose text changed. So do a bar's and a slice's when only their row changed, as a line's already did, so a decoration that reads a field the chart doesn't plot follows it. An effect that redraws on every change does a little more work; nothing needs to change in your code.
- **Hover dims the other marks' bodies, not their labels**, on the bar and donut charts and in a chart switch. The names and values of the marks that aren't hovered stay at full strength, so they keep 4.5:1 (WCAG 1.4.3); they used to dim with their marks, to 2.0:1 in the light theme. `--ec-dim-opacity` keeps its default, 0.3, and an effect's `opacity` on a dimmed mark still multiplies with it. `expressive()`'s `dim` doesn't change. To dim the labels too, as before, add this to the page's CSS: `.ec-chart.ec-hovering .ec-mark:not(.ec-hot) :is(.ec-label, .ec-value) { opacity: var(--ec-dim-opacity, 0.3); }`.

## 0.1.0 (24 October 2026)

The first release, published to npm from CI with provenance. Everything in it is new. [docs/api.md](https://github.com/Deaversbp/expressive-charts/blob/main/docs/api.md) documents every export.

### What's in it

- **The motion core.** One clock and three modes: Presentation (data transitions staged over about a second), Analysis (at most about 200 ms, unstaged) and Off. The device's reduced-motion setting turns motion off unless the viewer picks a mode on the page; a mode the page sets in code never overrides it. With motion off, every animation jumps to its end state. `motion` and `createMotion`, the clocks (`defaultClock`, `createClock`, `manualClock`), `tween`, `animated` with its interpolators, the easings, and `playback`, which plays a value through a range.
- **Bar, donut and line charts.** `barChart` draws bars or columns, plain or stacked; `donutChart` shares of a total; `lineChart` a line per series, on a number axis or a time axis. Each sizes itself to its container, follows the light or dark theme, gives every mark a key, and has a tooltip, a legend, a data table and keyboard focus, with announcements as an option. Colours follow the entity, not its rank (`colorAssignment`). The handle has `update()`, which animates a change by the motion mode (in Presentation, values first and then positions), `on()` for mark events, `marks()`, `focus(key)`, `leave()`, `labels()` and `destroy()`.
- **Switching between charts.** `chartSwitch` shows views of the same data in one place, and turns each mark into its partner in the next with `morph()`.
- **Adapters.** `expressive()` brings the same effects, keyboard focus and names to SVG marks drawn by D3, Observable Plot or by hand. It draws on an overlay and leaves the host's styling alone. `fromVegaView()` does the same for Vega and Vega-Lite charts rendered as SVG, and `samplesAlong()` gives data effects their samples on such marks.
- **Effects.** `travel` carries an icon along a mark, rolling, stepping or sliding (`gaits`); `flash`, `wiggle` and `pulse` draw attention without changing a value; `threshold` colours a mark where it's below or above a reference; `morph` turns one mark into another. `sequence`, `parallel`, `stagger` and `only` put effects together. Each goes in an effect slot (`hover`, `enter`, `update`, `exit`, `decorate`), as an effect or a preset's name, and `registerPreset` adds names.
- **Icons.** A neutral core set in theme colours (`icons`: a dot, an arrow and a chevron), `defineIcon` and `iconFromSvg` for your own, `registerIcon` and `registerIcons` to use them by name, and a ball and a boot in `expressive-charts/icons/sport`.
- **Controls.** `motionSwitch()`, the viewer's own choice of mode, kept across pages if you ask; `playButton()`, the Play/Pause button for a playback (WCAG 2.2.2).
- **Styling.** One injected stylesheet, or `expressive-charts/style.css` as a file; `--ec-*` custom properties for theming; and `configure()` for a Content-Security-Policy nonce, or for injecting nothing.
- **The effect-author API**, under the 0.x promise above: `defineEffect`, `defineDataEffect`, `describe`, `matrix`, `offset` and the contracts, with `expressive-charts/testing` (`checkEffect`, `checkTransition`) to check an effect on every kind of mark.
- **Accessibility.** Each chart is a named group and each mark one named image. A data table follows every chart, keyboard focus plays the hover effects, Escape ends a hover, and nothing plays by itself. The demo pages are checked against WCAG 2.2 AA, with axe's rules in Chromium, Firefox and WebKit, and with screen-reader scripts for NVDA + Chrome.
- **Packaging.** ES modules and CommonJS, each with its own types, which need TypeScript 5.4 or newer. No runtime dependencies and no side effects in its JavaScript, so a bundler keeps only what a page imports. A script-tag bundle defines one global, `ExpressiveCharts`. Node.js 22 or newer imports it with no DOM.

### In more detail

What each part does, and behaviour worth knowing:

- **The effect-author API** ([guide](https://github.com/Deaversbp/expressive-charts/blob/main/docs/effects-guide.md)). `defineEffect(spec)` and `defineDataEffect<D>(spec)` make an effect from its `run` and `end`: they fill in the kind and a `clear()` that does nothing, throw a `TypeError` without `run` or `end` (every effect needs an end state), and freeze the effect. A data effect's spec is checked against its row type strictly.
- **`expressive-charts/testing`**, a separate entry with the conformance suite. `checkEffect(effect, { marks, icons, data, batch, moved, name })` runs five checks on every mark (a full run ends as `end()` draws; clearing leaves nothing; an abort settles; with motion off no frames run; after a run or `end()`, a `change()` to the mark moved somewhere else leaves what `end()` draws there) and throws one `Error` listing every failure, in any test runner. The fixtures have moved twins for the fifth check; a page's own marks pass `moved(mark)` or skip it. With it: `fixtures` (one of each kind of mark), `testContext` and `play`.
- **`threshold({ compareTo, when, color })`** is the built-in data effect. It colours the parts of a mark's walk where its values are below a constant or a related series (`when: "above"` for above), in `"negative"` by default, with crossings interpolated between samples. A series is matched by `at` where both have it, else by `t`, and goes in `needs.related`. It draws at once, with no animation, and redraws on every change, so it belongs in `on.decorate`.
- **`samplesAlong(mark, points)`** gives data effects their samples on marks the library didn't draw. It projects each point `{ x, y, value, at? }`, in the marks' coordinates, onto the nearest point of the mark's walk and returns the samples in `t` order; a point on the walk, such as a vertex of the line it drew, lands exactly there. It pairs with `expressive()`'s `samples` option, and its points' type is `SamplePoint`.
- **`expressive()`'s `watch` option** follows the host's own transitions frame by frame, without `refresh()`. A `MutationObserver` notes the marks' geometry attributes, and `transform` and `style` on their ancestors up to the `<svg>`; once a frame, only the marks that moved are read again (their rows, geometry and samples), and their effects follow with no events. `refresh()`, called when the host joins new data, still fires `enter`, `update` and `exit`. It's opt-in: its cost grows with the number of marks that move each frame.
- **Transition effects.** `TransitionEffect`'s `run(from, to, ctx)` and `end(from, to, ctx)` take a `TransitionContext`: an `EffectContext` with `start`, from 0 to 1, so a run can begin part way and a switch back mid-way retraces. Its `mark` does nothing and its `onChange` never fires, since both views' marks are hidden while a transition plays.
- **`checkTransition(effect, { pairs, icons, name })`** in `expressive-charts/testing` checks a transition effect on pairs of marks, both ways: checks 1 to 4 of `checkEffect`, a run from `start: 0.5`, and that a run back from `start: 1 − p` begins with the picture the run forward draws at p. Its default pairs are `fixturePairs`: a slice and a column, a bar and a column, two slices, two lines and two points.
- **`morph({ points, align })`** is the built-in transition effect. It samples two closed outlines at `points` (default 160) and moves each point in a straight line to its partner, as one filled path; two lines are sampled along their strokes, their width moving between thicknesses; a closed and an open outline crossfade. `align: "unroll"` matches each side with the same side, and `"drop"` turns the matching by a side from the mark that goes round its pivot, so a slice's outer arc meets a column's top. The default is `"unroll"`, picked by comparing the two in the morph demo. 950 ms base with `transition` timing, eased in and out; a run from `start` takes the rest of the time.
- **`chartSwitch(target, { views, initial, transition, colors, announce })`** shows views of the same data in one place, one at a time, and turns each mark into the mark with its key in the next with a transition effect, `morph()` by default. Each view is a function that draws its chart in the container it's given, with the switch's `ColorAssignment`. Labels move between their places and swap their text half way, unmatched marks fade, and the old view's other parts fade out as the new one's fade in. A `show()` back mid-way reverses from where the shapes are. Only the shown view can be seen, reached or read, focus on a mark follows its key, and `announce` says the new view's label. It returns `{ show(view), current, chart(view), destroy() }`.
- **Dates on `lineChart`'s x.** An `x` that gives `Date`s makes a time axis, with no dependency. Its ticks fall on second, minute, hour, day, week, month and year boundaries, at both ends and a step of about a quarter of the range, each worded for its level in the page's locale through `Intl.DateTimeFormat` ("2026", "Apr", "Feb 8", "3:00 PM"). Each x is said as a medium date ("Jan 5, 2026", with the time when any x has one) in its name, the tooltip's title, the table's row headers and announcements, and `xFormat(x)` words it instead. `timeZone` is `"UTC"` (the default) or `"local"`. A date's key is its ISO string (`goals@2026-01-05T00:00:00.000Z`), samples' `at` is a `Date`, and `reveal()` takes a `Date` or its time in ms. Numbers and dates together throw a `TypeError`, as does an invalid `Date`. `LineChartOptions.x` is `Accessor<D, number | Date>`.
- **`update({ on })`** swaps a chart's effects in place, on the bar, donut and line charts: a changed slot's runs are cleared and the new effect starts where they were. `decorate` starts again on every mark, a held hover replays with the new hover effect once the change settles, and `enter`, `update` and `exit` draw the new effect's end state, so nothing enters again. Focus stays, and a slot given the same effect or preset name keeps its runs. An unknown preset name rejects before anything changes.
- **`leave()`** on every chart handle ends its hover, pointer or keyboard, as the viewer moving away would, and fires `leave`. Focus stays where it is. A chart switch ends the old view's hover with it, so `ChartSwitchView` has `leave()` too.
- **`table.series`** heads each series' column in the data table, `{ shots: "Shots" }`, defaulting to its `seriesLabels` name. It names a donut's value column without renaming its slices or its centre.
- **`fromVegaView(view, options)`** attaches effects to a Vega or Vega-Lite chart rendered as SVG. It reads the named mark (`mark`, Vega-Lite's `"marks"` by default) from the View's scenegraph: rects are bars (stacks too), arcs slices, symbols points and lines lines. `sample(row)` gives data effects each item's value and `at`. It takes `expressive()`'s other options, and follows the View's own renders, new data or a resize, with no `refresh()` to call. Duck-typed on the View: the library imports nothing from Vega, which stays a dev dependency.
- **Icons from icon sets.** `iconFromSvg` keeps `polyline` beside `path`, `circle`, `rect`, `ellipse`, `line` and `polygon`, drawn as a polygon left open, and `currentColor`, in any case, becomes the `text` token. So an icon copied from a set such as Lucide, Heroicons or Tabler follows the chart's theme, not the page's `color`. Fill rules and opacity aren't kept, so a solid icon's holes can fill in. The Icons section of docs/api.md has a recipe.
- `sequence` starts each part on the mark's geometry and data as they are when that part starts, not as they were when the sequence started, so a part after a travel follows a line that grew meanwhile.
- `onChange` listeners in the `update` slot get data that keeps the previous values the run was given, so `stagger` and `sequence` keep them when they start an effect on the latest data.
- `expressive()`'s hovered mark under `dim: true` takes its strong colour as our charts' marks do: its colour stepped a quarter of the way toward `--ec-text` (in OKLab), so lighter in the dark theme. `emphasis` on host marks mixes toward the same colour.
- `expressive()` reads a `<rect>` through its parent's coordinates and its own `transform` attribute, not through its own screen CTM, so the CSS transform an effect gives a bar is never read back as geometry. A CSS transform a host puts on the rect element itself isn't seen either (on its groups, it is).
- **CommonJS has its own types.** Each entry's `require` condition points at `.d.cts` declarations, so a CommonJS project resolving with `node16` is given CommonJS types for the `.cjs` file it loads. `import` has the `.d.ts` files.
- The types need TypeScript 5.4 or newer, since they use `NoInfer`. Under the old `node10` resolution, TypeScript can't find the subpath entries' types.
- The package includes this changelog, where the promise is.
- **Escape dismisses a pointer's hover.** While something is hovered, Escape anywhere on the page ends the hover and hides the tooltip, as `leave()` does, so the tooltip can be dismissed without moving the pointer (WCAG 1.4.13). An Escape the page has already handled is left alone.
- With `markLabel`, `expressive()` takes an `img`, `graphics-symbol` or `graphics-object` role (and its `aria-roledescription`) off unnamed host elements around the marks it names, as Vega gives the groups round its lines, so each mark is read once, by its name. `destroy()` puts them back.
- Under forced colours (Windows contrast themes), the motion switch's pressed mode shows in `Highlight` and `HighlightText`.
